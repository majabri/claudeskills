# PM L2 — Lead & Govern

Program governance tier. Altitude: multiple projects/teams, shared resources, organizational governance.

## What belongs at L2

- PMO design (supportive / controlling / directive models)
- Portfolio intake, prioritization, capacity allocation
- Program roadmap, shared resource coordination
- Steering committees: agenda, escalation, decision frameworks
- Program budget tracking, burn rate, ROI
- Cross-team dependency mapping and management
- Agile transformation governance
- OKR alignment: connecting projects to Key Results
- Change control board setup and operation
- Benefits realization tracking

## PMO Models

| Model | Role | When |
|---|---|---|
| Supportive | Templates and coaching on request | Low maturity; teams resist control |
| Controlling | Mandates standards; audits | Regulated; governance failures |
| Directive | PMO manages projects directly | High complexity; few experienced PMs |

## Portfolio Prioritization Scoring

Score each project on: Strategic alignment (30%), Value potential (25%), Risk if not done (20%), Cost/effort (15%), Dependencies (10%). Apply portfolio balance test. Then map approved projects to team capacity — don't approve more than capacity allows.

## Governance Cadence

| Cadence | Forum | Purpose |
|---|---|---|
| Weekly | Program standup | Dependencies, blockers |
| Bi-weekly | Health review | RAG, risks, changes |
| Monthly | Steering committee | Portfolio decisions, budget |
| Quarterly | Portfolio review | OKR alignment, intake |

## OKR Alignment

Cascade: Org OKRs → Team OKRs → Project objectives → Sprint goals.
Every active project traces to at least one Key Result. If it doesn't → either the OKR is missing or the project shouldn't exist.

## Change Control Process

1. Change request raised → logged by PM
2. Impact assessment (scope, timeline, cost, risk)
3. Change control board review (approve/reject/defer)
4. Update plan baseline if approved
5. Communicate to stakeholders and team
