# Lean & Six Sigma Reference

## When to Load This
Load for process improvement, waste reduction, DMAIC, value stream mapping, operational PM, or Lean-Agile combinations.

## Five Lean Principles
1. Value (customer perspective) | 2. Value Stream (map every step) | 3. Flow (no interruptions) | 4. Pull (produce what customer pulls) | 5. Perfection (continuous improvement)

## 8 Wastes — DOWNTIME
| Letter | Waste | Knowledge Work Example |
|---|---|---|
| D | Defects | Rework; bugs shipped to prod |
| O | Overproduction | Features nobody uses |
| W | Waiting | Blocked tickets; waiting for approvals |
| N | Non-utilized talent | PMs doing admin |
| T | Transportation | Handoffs; unnecessary meetings |
| I | Inventory | Unfinished work in progress |
| M | Motion | Context switching; tool hunting |
| E | Extra-processing | Reports nobody reads |

## Six Sigma
Goal: <3.4 defects per million opportunities (6σ). Data-driven variation reduction. Developed at Motorola 1986.

## DMAIC Framework
**Define**: Problem statement, project charter, VoC, SIPOC map
**Measure**: Baseline performance, measurement system analysis, data collection plan
**Analyze**: Fishbone/Ishikawa, 5 Whys, Pareto analysis, hypothesis testing
**Improve**: Solution generation, pilot, FMEA, implement
**Control**: Control plan, SPC charts, standard work, handoff to process owner

## Value Stream Mapping (VSM)
1. Define scope (product/service family)
2. Draw current state (every step + cycle time + wait time + %C&A)
3. Identify waste (waiting, rework, batching)
4. Design future state
5. Build improvement plan

## Lean-Agile Connection
Pull systems → Kanban | Flow → sprint throughput | Continuous improvement → retrospectives | Waste elimination → streamline ceremonies

## When to Use DMAIC vs Retro
DMAIC: stable measurable process with defects; weeks–months; statistical validation
Retro: team process; per sprint; qualitative + quick actions

## Failure Modes
- DMAIC running 6+ months → scope to 90-day cycles; timebox Analyze phase
- Improvements don't stick → treat as org change; involve the team
- Measuring output not root cause → use fishbone + 5 Whys
