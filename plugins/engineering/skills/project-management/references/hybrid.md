# Hybrid Project Management Reference

## When to Load This
Load when blending waterfall and agile, applying PRINCE2 Agile, working in regulated industries with iterative delivery, or needing both governance rigour and agile flexibility.

## When to Choose Hybrid
- Regulated industry (pharma, finance, gov) + product development
- Large fixed-price contract with changing internal requirements
- Org transitioning from waterfall to agile
- Some workstreams predictable, others exploratory

## Common Hybrid Models

**Model 1: Waterfall Envelope + Agile Execution**
[Initiation] → [Phase Plan] → [Sprints within phase] → [Stage Gate] → [Next Phase]
Stage gates = governance checkpoints. Sprints = delivery inside each phase.

**Model 2: Rolling Wave Planning**
Near-term: detailed backlog with acceptance criteria. Beyond 3 months: epics and milestones only. Re-plan at stage boundaries.

**Model 3: Parallel Workstreams**
Predictive stream: infra, procurement, compliance (Waterfall)
Adaptive stream: software, UX, product (Scrum/Kanban)
Single PM coordinates dependencies.

**Model 4: PRINCE2 Agile**
PRINCE2 stage governance + agile delivery inside stages. Fix time/cost; flex scope.

## Hybrid Change Control
Inside a stage: PO can reprioritize backlog freely (not a formal change).
Stage-level commitments (milestones, budgets, deliverables): formal change control required.
Define a Change Authority to approve low-impact changes without board escalation.

## Hybrid Metrics
RAG (weekly) + Milestone forecast (monthly) + Sprint velocity (per sprint) + EVM CPI/SPI (monthly for fixed-price)

## Failure Modes
- "Wagile" → sprints as status checkpoints; no real agile delivery
- No clear governance boundary → document what changes at stage vs. sprint level
- Documentation kills velocity → heavy docs at stage level only; lean at sprint level
