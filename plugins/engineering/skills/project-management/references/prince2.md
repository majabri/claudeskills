# PRINCE2 Reference

## When to Load This
Load for PRINCE2 7, formal stage management, governance-heavy environments, UK/EU public sector, structured project control, or PRINCE2 Agile.

## Core Philosophy
Every project must be continuously justified. If the business case fails, the project should stop.

## The 7 Principles
1. Continued business justification | 2. Learn from experience | 3. Defined roles & responsibilities | 4. Manage by stages | 5. Manage by exception | 6. Focus on products | 7. Tailor to the project environment

## The 7 Practices
Business Case | Organizing | Quality | Plans | Risk | Issues | Progress

## The 7 Processes
| Process | When | Key Output |
|---|---|---|
| Starting Up (SU) | Before project | Project Brief |
| Initiating (IP) | First stage | PID |
| Directing (DP) | Throughout | Board decisions |
| Controlling a Stage (CS) | Each stage (PM) | Work packages |
| Managing Product Delivery (MPD) | Each stage (teams) | Completed work |
| Managing Stage Boundary (SB) | Stage end | Next Stage Plan |
| Closing (CP) | Project end | End Project Report |

## Project Board Roles
Executive (owns business case) | Senior User (represents users) | Senior Supplier (represents delivery)

## Management by Exception
Tolerances set per stage (time, cost, scope, risk, quality, benefit). PM manages within them. Tolerance breached → Exception Report → Board decides. Senior management only involved when needed.

## The PID (Project Initiation Documentation)
Project definition + business case + approach + controls + quality/risk/comms plans + project plan + team structure

## PRINCE2 vs PMBOK
| | PRINCE2 | PMBOK 7 |
|---|---|---|
| Type | Methodology (prescriptive) | Standard (principles) |
| Governance | Strong; Project Board | PM-centric |
| Business Case | Mandatory; re-validated | Recommended |
| Geography | UK/EU | Global |

## PRINCE2 Agile
PRINCE2 controls what/when (stage boundaries). Agile controls how (sprints inside stages).
5 targets: On time | On budget | Protected quality | Easy to use | Embracing change
Fix time and cost; flex scope.

## Failure Modes
- Paperwork theater → tailor; remove what adds no value
- Board disengaged → reinforce board accountability
- Business case not maintained → re-validate at every stage boundary
